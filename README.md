# OsonIjara — Flutter App

A Flutter implementation of the OsonIjara rental-listing app, matching the
provided wireframes, styled with a premium navy / ocean-blue / gold color
palette, and connected to the real FastAPI backend (see `oson_ijara_backend/`).

## Run it

```bash
flutter pub get
flutter run
```

## What's included
- Login & Register screens
- Home feed with search bar, filter button, and property cards
- Property detail screen (photo carousel, expandable description, amenities, owner card, save/bookmark)
- Filter screen (price range slider, bedroom/bathroom selectors, student toggle)
- Saved ("Saralangan uylar") screen with empty-state and live bookmarked list
- Add listing ("E'lon berish") screen that adds a new card to the Home/Saved feed
- Profile & Edit profile screens
- Shared bottom navigation (Home / Saved / Add / Profile)

## Connected to the real backend
The app now talks to the OsonIjara FastAPI backend instead of in-memory mock data:
- Real login/register (`AuthStore`) — the JWT is kept in memory only; closing the
  app returns you to the Login screen (no persisted session yet).
- The property feed, search, and filters all read from `GET /properties`.
- Bookmarking, creating a listing, and editing a listing all call the API and
  update the UI optimistically.
- A listing's owner name/phone/avatar now come from the real account that created
  it, shown wherever the wireframes showed "Foydalanuvchi".
- Real uploaded photos display with `Image.network`; listings without photos
  still show the gradient placeholder.
- Picking and uploading photos (avatar and property listings) is fully wired up
  via `file_picker` + `POST /properties/{id}/images` / `/users/me/avatar`.

### Point it at your backend
Edit `lib/config/api_config.dart` — `ApiConfig.baseUrl` must match how your device
reaches the API:
- Android emulator → `http://10.0.2.2:8000` (already the default)
- iOS simulator / web / desktop → `http://localhost:8000`
- A physical phone → `http://<your-computer's-LAN-IP>:8000`, same Wi-Fi as your computer

### Required one-time platform setup
This zip only ships `lib/` and `pubspec.yaml` — no `android/`/`ios/` folders, since
those need to be generated by the Flutter tool itself (they contain files specific
to your Flutter SDK version, package name, etc.). Before your first run:

```bash
flutter create .      # generates android/, ios/, and the other platform folders
flutter pub get
```

Then, because the backend runs over plain HTTP (no TLS) during development, both
Android and iOS block that traffic by default — you'll need to explicitly allow it:

**Android** — open `android/app/src/main/AndroidManifest.xml` and add
`android:usesCleartextTraffic="true"` to the `<application ...>` tag:
```xml
<application
    android:label="oson_ijara"
    android:usesCleartextTraffic="true"
    ...>
```

**iOS** — open `ios/Runner/Info.plist` and add, inside the outermost `<dict>`:
```xml
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsArbitraryLoads</key>
    <true/>
</dict>
```

Both of the above are fine for local development but should be tightened (or
removed, once the backend serves HTTPS) before shipping to real users.

## Notes
- No persisted login session yet — closing the app signs you out (see "Connected
  to the real backend" above). Adding `shared_preferences` or `flutter_secure_storage`
  to keep the JWT across restarts is a reasonable next enhancement.
- Photos fall back to elegant gradient + icon placeholders whenever a listing (or
  user) has no real uploaded photo yet.
- Color tokens live in `lib/theme/app_colors.dart` — change them there to
  retheme the whole app in one place.

## Deploying the web build live (free, via Netlify)

Pairs with the backend deployment guide in `oson_ijara_backend/README.md` —
deploy the backend first so you have its live URL.

### 1. Build for the web, pointed at your live backend
`ApiConfig.baseUrl` is set at build time now, via `--dart-define`, instead of
needing you to hand-edit the file before every deploy:

```bash
flutter build web --release --dart-define=API_BASE_URL=https://your-backend.onrender.com
```

This produces a static site in `build/web/`.

### 2. Deploy `build/web/` to Netlify
1. Sign up at [netlify.com](https://netlify.com) (no card required).
2. From the dashboard, drag and drop the `build/web` folder onto the deploy area.
   (No Git connection needed for this — Netlify doesn't have the Flutter SDK
   preinstalled, so building locally and uploading the output is the simplest
   path. Wiring up a GitHub Action to build and deploy automatically on push
   is a nice follow-up enhancement.)
3. Netlify gives you a live URL like `https://oson-ijara.netlify.app` immediately.

### 3. Test it end to end
Open the Netlify URL, register a new account, create a listing, add a photo.
The first request after either service has been idle may take up to ~30–50s
(Render's free tier spinning back up) — the app pings the backend on launch to
get a head start on that, but a first-ever cold start can still be slow. This
is a free-tier trade-off, not a bug.

### Re-deploying after a code change
Repeat step 1, then drag the new `build/web` folder onto your existing Netlify
site (or run `netlify deploy --prod --dir=build/web` with the Netlify CLI once
it's installed and linked to the site).
